# 150 位模擬家長並發驗收規格
此文件是壓力測試計畫，不代表已通過實際測試。

- 在獨立 Supabase 專案中建立 150 位測試家長、150 位測試幼兒及關聯。
- 用測試 LINE adapter 攔截推播，不可連正式 LINE channel。
- 讀取階段：以 10、30、75、150 並發數分段執行家長登入後資料查詢。
- 寫入階段：模擬同日 150 筆臨托／延托申請及審核；對同一幼兒重複送出，需收到唯一約束錯誤而非建立重複紀錄。
- 接送階段：模擬兩位同班教師同時確認同一幼兒，只能成功一次；跨班教師必須被拒絕。
- 收款階段：兩個同時收費請求只能寫入一筆；請假及退款紀錄不能被當成未收款。
- 通知階段：行政只通知蔡青蓓與蔡妤瑄兩個已綁定的測試代理帳號；代課日不通知請假教師；通知失敗可以重試。
- 驗收門檻（目標非測試結果）：申請 p95 < 3 秒；非預期錯誤率 < 0.1%；跨班越權及重複收費均為 0。
- 需提供 RPS、p50/p95/p99、錯誤碼與成功率報告，才可聲稱通過 150 人並發測試。

## 尚存阻斷項目
正式 `pickup_records` 目前沒有紀錄，既有教師「已接送」按鈕僅處理已有紀錄的接送通知。
應先部署具權限、日期與唯一約束檢查的「當日課後接送首次建檔 + 完成」RPC；不可單獨把教師名冊加按鈕上線。
