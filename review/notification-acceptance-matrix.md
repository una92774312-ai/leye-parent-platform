# 試行班級通知規格（待實測）

僅開放 C01 櫻桃班及 C02 蘋果班家長。使用事件觸發、按使用者去重，同一事件同一 LINE ID 不重送。

| 事件 | 家長 | 原班 | 課後 | 行政 |
|---|---|---|---|---|
| 請假 | 頁面確認 | 通知 | 有課後才通知 | 待辦 |
| 臨托／延托送出 | 頁面確認 | 通知 | 暫不通知 | 待辦及必要時通知 |
| 核准 | 通知 | 通知 | 指定課後班通知 | 系統更新 |
| 拒絕／候補 | 通知 | 有必要才通知 | 不通知 | 系統更新 |
| 改班 | 通知 | 通知 | 舊班撤銷、新班安排各通知 | 系統更新 |
| 提早接送 | 頁面確認 | 無課後才通知 | 有課後才通知 | 系統更新 |
| 晚到 | 頁面確認 | 無課後才通知 | 有課後才通知 | 系統更新 |
| 已接送 | 系統狀態，可選推播 | 無 | 無 | 紀錄 |
| 收費 | 系統更新，可選收據 | 無 | 無 | 月報 |
| 18:05仍未接回 | 通知 | 無 | 系統警示 | 通知 |

## 發送前檢核
- 以事件當日有效指派之 aftercare_class_id 為唯一通知班級，不可使用原始預設班級取代已核准轉班。
- 老師當日有排班者優先，無當日排班才使用固定指派。
- line_user_id 未綁定時記錄 skipped，並顯示在行政待辦供人工追蹤。
- 更改課後班發送新舊班訊息；需要事件版本 key 確保冪等。
- LINE Messaging API 的推播由帳號各自計費；僅 UI 狀態改變不需要發訊息。

## 封鎖正式合併的驗收項
- 一般課後幼兒可能只有 aftercare_plans / roster，沒有 pickup_records；teacher_complete_pickup 需要 pickup_records ID，不能視為完整接通。
- 提早接送若是 requests.pickup_early 而非 pickup_records 來源，當前教師按鈕不會出現。
- 缺少可用於端對端測試的真實教師 LINE session，不能用 service_role 假冒真實教師驗收。
- 真實 LINE 綁定碼失敗後同帳號重試需以受控帳號完成，不得使用真實家長測試錯誤注入。
